# Бэкенд трекера задач

FastAPI, PostgreSQL, SQLAlchemy и Alembic. Точка входа — `app.main:app`.
Авторизация использует существующую сессионную cookie; все API задач, групп
и приглашений требуют входа. Схемы запросов и ответов доступны в `/docs`.

## Запуск

Установить зависимости через `uv sync`, настроить `.env` по `.env.example`
и запустить PostgreSQL через `docker compose -f docker-compose.local.yml up -d`.
Перед запуском приложения применить миграции:

```bash
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

## Задачи

Все пути ниже имеют префикс `/api/v1`.

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/tasks` | Создать личную или групповую задачу |
| GET | `/tasks` | Получить доступные задачи |
| GET | `/tasks/{task_id}` | Посмотреть задачу |
| PATCH | `/tasks/{task_id}` | Изменить задачу, исполнителя или статус |
| DELETE | `/tasks/{task_id}` | Удалить незавершённую задачу |

Пример создания групповой задачи:

```json
{
  "title": "Купить продукты",
  "description": "Молоко и хлеб",
  "priority": "normal",
  "group_id": "UUID группы",
  "assignee_id": null
}
```

`title` обязателен и не может состоять из пробелов. `description` необязателен.
Приоритеты: `low`, `normal`, `high`; по умолчанию — `normal`.
Без `group_id` создаётся личная задача. Без `assignee_id` задача не назначена.
Исполнитель групповой задачи должен состоять в группе; личную задачу можно
назначить только себе.

Новая задача имеет статус `open`. Статусы `open` и `in_progress` можно менять
между собой; из обоих можно перейти в `completed`. Выполненная задача доступна
только для просмотра: любое изменение и отдельное удаление возвращают `409`.
При удалении группы её выполненные задачи также удаляются.

Личные задачи доступны только автору. Любой участник группы может создавать,
редактировать, назначать, выполнять и удалять её незавершённые задачи, включая
задачи других участников. Выполнить задачу может любой участник независимо
от назначенного исполнителя. Автор и принадлежность задачи не меняются.

`PATCH` изменяет только переданные поля. `description: null` очищает описание,
`assignee_id: null` снимает назначение. Название, приоритет и статус нельзя
очистить через `null`.

`GET /tasks` возвращает личные задачи пользователя и задачи всех его групп,
от новых к старым. Доступны совместимые фильтры `group_id`, `status`,
`assignee_id`. Чужие личные задачи и задачи недоступных групп возвращают `404`.

## Группы

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/groups` | Создать группу: `{"name": "Семья"}` |
| GET | `/groups` | Получить свои группы |
| GET | `/groups/{group_id}` | Посмотреть свою группу |
| DELETE | `/groups/{group_id}` | Удалить группу (владелец) |
| GET | `/groups/{group_id}/members` | Получить участников |
| DELETE | `/groups/{group_id}/members/{user_id}` | Исключить участника (владелец) |
| POST | `/groups/{group_id}/leave` | Выйти из группы |

Создатель становится владельцем и участником группы. Один пользователь может
состоять в нескольких группах. Владелец не может выйти или исключить себя;
передача владения не предусмотрена. Обычные участники могут выходить сами.

После выхода или исключения доступ к группе прекращается. Созданные участником
задачи остаются в группе. Его назначения на незавершённых задачах снимаются,
а выполненные задачи сохраняются без изменений.

Удаление группы окончательно удаляет её задачи, членства и приглашение.
Учётные записи пользователей, их личные задачи и другие группы сохраняются.

## Приглашения

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/groups/{group_id}/invitation` | Создать или заменить приглашение (владелец) |
| DELETE | `/groups/{group_id}/invitation` | Отозвать приглашение (владелец) |
| GET | `/invitations/{token}` | Узнать название и ID группы без вступления |
| POST | `/invitations/{token}/accept` | Подтвердить вступление |

Ответ создания содержит `group_id`, `token`, `created_at`. Фронтенд использует
`token` в ссылке на свой экран приглашения. После входа или регистрации этот
экран запрашивает сведения о группе и вызывает `accept` только после
подтверждения пользователя. Этот репозиторий реализует только бэкенд.

Приглашение многоразовое, без срока действия; у группы одно действующее
приглашение. Повторное создание немедленно отзывает прежний токен. В БД хранится
только хэш; исходный токен возвращается при создании. Повторное принятие
действующего приглашения уже вступившим участником безопасно. Отозванные,
заменённые и удалённые вместе с группой приглашения возвращают `404`.

## Проверки

```bash
uv run pytest
uv run ruff check app tests
```

Интеграционные тесты запускаются только с `AUTH_TEST_DATABASE_URL`, указывающим
на **отдельную тестовую PostgreSQL БД**. Они применяют миграции через Alembic
и удаляют созданные тестовые данные. Без этой переменной интеграционные тесты
пропускаются. Обычный `DATABASE_URL` вместо неё не используется.
